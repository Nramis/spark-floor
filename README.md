# Ориентир Пол / Spark Floor

Android-приложение для экспериментального анализа пола по снимку:
выделение маски, оценка видимой дорожки, её длины и изгибов с голосовым описанием.
Текущая версия — **0.7**.

Экспериментальное автономное приложение Android 8+, ARM32/ARM64, без ARCore,
сервера и разрешения INTERNET. Сегментация пола: SegFormer B0 ADE20K,
ONNX Runtime Android 1.16.3. Веса нейросети в этой версии не изменены.

**Статус:** исследовательский прототип. Геометрия проверена синтетическими
тестами; реальные расстояния и работа версии 0.7 на телефоне пока не проверены.
Приложение не предназначено для самостоятельной навигации.

| Возможность | Реализация |
| --- | --- |
| Распознавание пола | SegFormer B0 / ADE20K, локально через ONNX Runtime |
| Визуализация | Маска пола, вписанная трапеция, осевая линия дорожки |
| Геометрия | Проекция на горизонтальную плоскость с учётом высоты и позы камеры |
| Результат | Приблизительная длина видимого участка и предполагаемые изгибы |
| Обратная связь | Текст и русская озвучка через Android Text-to-Speech |
| Поддержка | Android 8+, ARM32 / ARM64 |

Инструкции по сборке и тестированию приведены ниже. Большие веса модели,
APK, локальные настройки и ключи подписи не хранятся в Git.

## Новое в 0.7

- Розовая линия показывает предполагаемую ось видимого участка пола.
- Приложение сообщает текстом и голосом приблизительную длину линии,
  предполагаемые изгибы влево/вправо и их положение от начала видимой линии.
- Длина считается по изгибам в координатах пола, с учётом перспективы,
  высоты камеры, наклона, крена и сохранённой фокусной поправки.
- При разрыве маски, её разделении, резком сдвиге или обрезанной кадром
  боковой границе продолжение не достраивается.
- Калибровка и её сброс пересчитывают линию и описание текущего снимка.
- Жёлтая отметка выбранной точки сохранена; метры округляются до десятых.

Зелёный цвет — предполагаемый пол, голубой — прежняя вписанная трапеция,
розовый — новая осевая линия. Трапеция не ограничивает новую линию:
изгибающаяся дорожка может выходить за пределы прямой трапеции.

## Как проверить на телефоне

1. Измерьте высоту объектива над ровным полом и задайте её в сантиметрах
   (40–250). После изменения высоты сделайте новый снимок.
2. Держите телефон вертикально, задней камерой вперёд и немного вниз,
   неподвижно несколько секунд. Для первых испытаний используйте опору.
3. Снимите коридор, где видны обе боковые границы пола. Дождитесь анализа.
4. Прослушайте описание или откройте снимок для измерений. Длина относится
   только к участку между концами розовой линии; невидимый участок от ног
   пользователя до её начала в длину не входит.
5. Для проверки масштаба нажмите на известную точку пола. Для калибровки
   удерживайте палец на ней и введите расстояние по полу от точки прямо
   под объективом, а не наклонную дальность от объектива.
6. Проверьте другие точки рулеткой: совпадение на точке калибровки
   не подтверждает точность на остальных расстояниях.

На встроенном фото длина и метрические изгибы отключены: неизвестны
параметры и положение исходной камеры. Пример проверяет сегментацию и трапецию.

Для проверки изгибов используйте реальный изогнутый коридор, где видны
границы пола. Сначала отдельно проверьте прямой участок, затем левый/правый
изгиб и S-образный участок. Сравнивайте рулетку с концами отображённой линии.
Снимки с невидимыми границами, мебелью и развилками проверяют отказы алгоритма.

## Математическая модель

Для задней камеры и правильно ориентированного портретного кадра:

```
r = [(u-cx)/(fx*s), -(v-cy)/(fy*s), -1]
n = normalize(gravity_at_capture)
t = -h / dot(n, r)
Q = t*r + h*n
```

`Q` — точка пола относительно вертикальной проекции камеры, в осях устройства.
`h` — высота объектива, `s` — фокусная поправка. Расстояние до выбранной
точки равно `|Q|`. Поза фиксируется при съёмке и не зависит от наклона при просмотре.
Луч ближе примерно 5,7° к горизонту и точки далее 10 м отвергаются.

Для дорожки строится ортонормированный базис плоскости пола:

```
right = normalize(cross([0,0,-1], n))
forward = cross(n, right)
x = dot(Q, right)
z = dot(Q, forward)
```

Таким образом крен кадра не превращается в ложный изгиб. Обратная проекция
переносит маску в сетку пола с шагом 0,1 м, в области `x = -5..5 м`, `z = 0,1..10 м`.
Используются только наблюдаемые точки в пределах допустимого расстояния и угла луча.
Граница маски сужается на один пиксель; это фильтр пограничных ошибок,
а не физический запас ширины прохода.

Начало ищется в видимой центральной области до 3 м вперёд. На последовательных
поперечных сечениях выбираются перекрывающиеся интервалы пола. Разделение
на несколько интервалов останавливает линию. Середины сглаживаются в окне
до 0,7 м; каждый соединяющий отрезок повторно проверяется по маске с шагом
не более 2,5 см. Пропуски и препятствия не заполняются.

Длина — сумма евклидовых длин отрезков в метрах. Направления оцениваются на
базе 0,6 м; накопленное изменение направления от 18° считается предполагаемым
изгибом. Постоянный диагональный курс изгибом не считается. Сообщаются до
четырёх последовательных изгибов, с расстоянием вдоль линии от её видимого начала.

Одноточечная калибровка сохраняет прежний поиск общего множителя `fx,fy`
в диапазоне 0,5–2. Неоднозначные и малочувствительные случаи отвергаются.
Поправка применяется лишь при совпадении исходных углов обзора.

## Ограничения

Модель предполагает плоский горизонтальный пол и совпадение оптической оси
камеры с осью -Z устройства. Углы обзора от драйвера приблизительны;
кроп JPEG, монтажная поправка камеры, дисторсия и ошибки датчиков не измерены.
Нормаль оценивается по TYPE_GRAVITY либо сглаженному акселерометру.
Проверка неподвижности — эвристика; при движении её недостаточно для точных метров.

Ось маски не обязательно совпадает с реальной дорожкой: открытая комната,
асимметричная мебель и ошибки сегментации могут менять её форму. Используется
только класс ADE20K `floor` (3); распознавание уличных тротуаров и дорожек не добавлено.
Алгоритм следует вперёд по сечениям и не восстанавливает повороты на 90°,
развороты, закрытые участки, лестницы, уклоны или маршрут за пределами кадра.
Отсутствие выраженных изгибов не доказывает прямолинейность всей дорожки.

Физическая точность версии 0.7 пока не проверена. Не предназначено для
самостоятельной навигации. Маска, линия и трапеция не подтверждают отсутствие
препятствий и безопасность прохода. Первые испытания — с сопровождающим.

## Проверки и сборка

Чистые Java-тесты без Android (JDK 17+):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1
```

- `DistanceTest`: известные расстояния, точка сбоку, крен, калибровка и отказы.
- `TrapezoidTest`: пустая маска, прямоугольник, вырез препятствия, удалённый пол,
  разобщённая ближняя полоса.
- `FloorPathTest`: обратимость проекции с креном и фокусной поправкой,
  прямая/диагональная/левая/правая/S-образная дорожки, длина кривой,
  остановка перед разделением и разрывом, отказы при обрезанных границах,
  слишком коротком участке, удалённой маске и отсутствии позы.

Обычная сборка: Android Studio / Gradle, AGP 8.7.3, совместимая версия Gradle,
JDK 17+, compileSdk 35, minSdk 26. В рабочей папке также присутствует Gradle Wrapper.
Перед первой сборкой выполните `python download_model.py` — веса проверяются по SHA256.

Резервная сборка этого проекта непосредственно через установленные SDK tools:

```powershell
python tools/build_local.py
```

Нужны JDK 17+, Android SDK platform 35 и build-tools 35+. При необходимости
задайте `JAVA_HOME` и `ANDROID_SDK_ROOT`. Скрипт проверяет SHA256 модели
и AAR ONNX, компилирует Java/DEX, упаковывает ARM32/ARM64 и подписывает APK.
Это специализированная сборка текущего проекта без собственных Android-ресурсов.

Результат: `build/outputs/apk/local/spark-floor-0.7-debug.apk`.
Локальный отладочный ключ хранится в `build/local-debug.keystore`.
Он отличается от ключа исходного распространённого APK: установка поверх
прежней версии с другой подписью потребует её удаления с потерей настроек.
При повторной сборке сохраняйте локальный ключ для обновления этой сборки.

Проверено: три набора Java-тестов, компиляция Android-кода, сборка APK,
подпись v2/v3, выравнивание, версия, ABI и разрешения. Gradle-сборка в текущей
среде не завершилась из-за TLS при загрузке зависимости Google Maven;
резервная сборка SDK tools завершилась успешно. Телефон через ADB не подключён;
запуск, интерфейс, речь, скорость и реальные расстояния на нём не проверены.

## Исходники и лицензии

`FloorDistance.java` — пересечение луча с полом и одноточечная калибровка.
`GroundProjection.java` — проекция между снимком и координатами пола.
`FloorPath.java` — осевая линия, длина и изгибы, без зависимостей Android.
`DistanceSupport.java` — датчики, настройки, калибровка, линия и выбор точки.
`MainActivity.java` — камера, ONNX, интерфейс и озвучивание.
`Segmentation.java`, `Trapezoid.java` — прежняя сегментация и трапеция.

Лицензии и источники находятся в assets. Сведения о лицензиях весов из
исходной версии сохранены в `SEGFORMER_LICENSE.txt`; перед распространением
продукта проверьте применимые условия. Исходный пример SUN RGB-D — Open3D
SampleSUNRGBDImage. Историческое совпадение Java/Python-масок IoU 0.999401
относится к проверке реализации сегментации версии 0.6, а не к точности
относительно истинной разметки и не к новой геометрии дорожки.
